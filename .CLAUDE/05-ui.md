# UI (`ui/`)

Interfaccia costruita con **Textual** (TUI). Testi utente-facing e notifiche interamente in
italiano, con emoji (🔍 📋 ➕ 🚀 📷 ecc.); commenti nel codice in inglese.

## `ui/app.py` — classe `YGOValuerApp(App)`

App principale Textual, contiene anche il CSS (stringa Python multi-linea, nessun file `.tcss`
separato) e gran parte della logica di business (vedi [02-architettura.md](02-architettura.md)).

- `compose()` — struttura a `TabbedContent` con 4 tab:
  - `tab_collection` → `CollectionView`
  - `tab_add` → `AddCardView`
  - `tab_bulk` → `BulkAddView`
  - `tab_grading` → `GradingView` (tab "🩺 Grading Carta (CV + AI)", ex "Scan da Immagine
    (OCR/Vision)")
- Gestori eventi centralizzati (dispatcher unico per tutta l'app):
  - `on_mount` — inizializzazione client API, storage, caricamento collezione
  - `on_input_changed` — filtro live della collezione
  - `on_button_pressed` — dispatcher per **tutti** i bottoni dell'app (incluse azioni bulk-add e
    scanner)
  - `on_data_table_header_selected` — sorting della tabella collezione (toggle direzione)
  - `on_option_list_option_selected` — selezione risultati ricerca
- Metodi di business principali:
  - `delete_selected_card`
  - `refresh_all_prices` — ri-interroga **CardTrader** (non più YGOPRODeck) per ogni carta in
    collezione e aggiorna i prezzi reali
  - `perform_card_search` — ricerca via YGOPRODeck (solo identificazione carta)
  - `add_selected_card_to_collection` (`async`)
  - `add_card_to_collection_logic` (`async`) — logica condivisa di aggiunta/incremento
    quantità, riusata dal flusso "Aggiungi Carta" singolo, dal bulk e dal salvataggio del
    Grading; chiama `CardTraderAPI.find_real_prices()` per il prezzo reale prima di
    creare/aggiornare il `CollectionItem`
  - `perform_bulk_load`, `process_bulk_add_current` (`async`), `commit_bulk_collection`,
    `process_bulk_skip`, `advance_bulk_queue` — pipeline dell'aggiunta massiva
  - `start_grading`, `_run_grading` (Textual worker), `perform_grading_search`,
    `save_graded_card_to_collection` (`async`) — pipeline del modulo di Grading (vedi sotto e
    [07-grading.md](07-grading.md))
- `action_quit` — override che chiude le sessioni httpx (`api.close()`, `cardtrader.close()`) e
  il grader (`grader.close()`) prima di uscire

## `ui/views/collection_view.py` — `CollectionView(Container)`

Tab "Collezione & Valutazione":

- `DataTable` con colonne: ID, Nome, Set Code, Rarità, Grade, Qtà, prezzi per ogni condizione,
  Totale NM, Valore Reale. Le colonne prezzo chiamano `item.get_price_for_condition(cond)`, quindi
  mostrano automaticamente i prezzi reali CardTrader quando disponibili (fallback a stima solo
  per le condizioni senza inserzioni attive) — nessuna colonna dedicata era necessaria per questo
- Barra metriche: carte uniche, pezzi totali, valore NM
- Barra condizioni: stime EX/GD/LP/PO — anche questa calcolata via `get_price_for_condition`
  (non più con `CONDITION_MULTIPLIERS` applicato direttamente), quindi riflette i prezzi reali
- Filtro testo + filtro prezzo minimo
- Sorting cliccabile per colonna con toggle di direzione

## `ui/views/add_card_view.py` — `AddCardView(Container)`

Tab "Aggiungi Carta":

- Input di ricerca (nome, passcode, o set code)
- Due `OptionList` affiancate: carte trovate / set-rarità disponibili per la carta selezionata —
  **nessun prezzo mostrato** in queste liste o nel riepilogo di conferma (`update_add_form`): il
  prezzo YGOPRODeck non viene più calcolato/mostrato da nessuna parte, il prezzo reale si scopre
  solo dopo la conferma, quando `add_card_to_collection_logic` interroga CardTrader
- Form di conferma con selezione quantità

## `ui/views/bulk_add_view.py` — `BulkAddView(Container)`

Tab "🚀 Aggiunta Bulk": permette di incollare più codici set (separati da spazio o a capo) in una
`TextArea`. L'app risolve i codici in batch via YGOPRODeck (rispettando il rate limit) e presenta
all'utente, uno alla volta, la conferma/scarto della versione/rarità corretta (senza mostrare
prezzi, stesso motivo di `AddCardView`) prima del salvataggio definitivo (`btn_bulk_save_all`).
Internamente ogni elemento della coda è un dict `{"query", "results", "added", "skipped"}`
mutato in-place mentre l'utente avanza nella coda.

## `ui/views/grading_view.py` — `GradingView(Container)`

Tab "🩺 Grading Carta (CV + AI)" — sostituisce interamente `ScannerView` (rimossa). Flusso in due
fasi:

1. **Analisi**: input testuale per il path immagine (stesso pattern del vecchio scanner), più un
   bottone "📂 Browse" che apre `ImagePickerScreen` (vedi sotto) per selezionare il file da un
   albero di directory invece di scrivere il path a mano, e il bottone "Analizza Carta". Il
   risultato (`GradingResult`) viene mostrato con `display_grading_result()` — sotto-voti
   Centering/Edges/Surface, grade finale, condizione mappata, dettagli grezzi. Errori mostrati
   con `display_analysis_error()` (mai un traceback grezzo, sempre un messaggio comprensibile
   propagato da `CardDetectionError`/`InspectorAgentError`).
2. **Collegamento alla collezione** (opzionale): stesso motore di ricerca di `AddCardView`
   (`display_search_results`, `display_sets_for_card`, `selected_card`/`selected_set`), ma su
   widget con ID prefissati `grading_*` per evitare collisioni con `AddCardView` nella stessa
   `TabbedContent` (i due tab restano entrambi nel DOM di Textual anche quando non visibili).
   Il bottone "Salva con Grade in Collezione" resta disabilitato finché non c'è sia un
   `GradingResult` sia una carta/set selezionati (`update_save_form()`).

L'analisi gira in un Textual worker lanciato da `YGOValuerApp.start_grading` (non un semplice
`await` diretto come le altre chiamate), con `grading_view.loading = True/False` per mostrare lo
spinner nativo di Textual senza codice custom — necessario perché la chiamata al VLM locale può
richiedere secondi o minuti su CPU.

## `ui/screens/image_picker_screen.py` — `ImagePickerScreen(ModalScreen[Optional[str]])`

Modal screen riutilizzabile per scegliere un file immagine dal filesystem, invocata dal bottone
"📂 Browse" di `GradingView` (ma non legata a quel tab specifico — potrebbe servire altrove in
futuro). Contiene un `ImageDirectoryTree` (sottoclasse di `DirectoryTree` che filtra via
`filter_paths()` mostrando solo cartelle e file con estensione `.jpg/.jpeg/.png/.bmp/.webp/.tiff`),
radicato di default in `Path.home()`. Alla selezione di un file (`on_directory_tree_file_selected`)
abilita il bottone "✅ Seleziona"; conferma o "❌ Annulla"/`Esc` chiudono la modal con
`self.dismiss(path_str)` o `self.dismiss(None)`.

`YGOValuerApp.on_button_pressed` la apre con
`self.push_screen(ImagePickerScreen(), self.set_image_path_from_browser)`: il secondo argomento è
una callback invocata al dismiss con il risultato (`Optional[str]`), che scrive il path scelto
nell'`Input` `#input_image_path` solo se non è `None` (Annulla non tocca il campo).
